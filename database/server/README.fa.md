# سرور احراز هویت واژه‌نگار چینی

بک‌اند OTP با **node:http خالص و بدون هیچ وابستگی npm** — پیامک کاوه‌نگار، ایمیل Resend، سشن توکنی و همگام‌سازی پیشرفت.

## اجرا

```bash
npm run api          # از ریشه word-atlas — پیش‌فرض http://localhost:8787
```

پایگاه‌داده فایل ساده‌ی `server/data/db.json` است (نوشتن اتمیک؛ خودکار ساخته می‌شود). برای پاک‌کردن کامل حساب‌ها فقط همین فایل را پاک کنید.

## تنظیمات

۱. از `server/.env.example` یک کپی با نام `server/.env` بسازید (سرور با `--env-file-if-exists` آن را خودکار می‌خواند).
۲. طبق جدول زیر کلیدها را پر کنید:

| متغیر | برای چه | کجا می‌گیرید |
|---|---|---|
| `KAVENEGAR_API_KEY` | پیامک OTP شماره‌های ایران | پنل kavenegar.com → تنظیمات → API Key |
| `KAVENEGAR_TEMPLATE` | الگوی تأیید کاوه‌نگار | پنل کاوه‌نگار → تنظیمات → الگوهای تایید؛ الگو باید `%token` داشته باشد و تأیید شده باشد |
| `RESEND_API_KEY` | ایمیل OTP | resend.com/api-keys |
| `EMAIL_FROM` | فرستنده ایمیل | دامنه تأییدشده در Resend؛ `onboarding@resend.dev` فقط به ایمیل خودِ حساب Resend می‌رسد (مناسب تست) |
| `PORT` | پورت سرور | پیش‌فرض 8787 |
| `EXTRA_ORIGINS` | دامنه‌های مجاز CORS اضافه | جدا‌شده با کاما |
| `NODE_ENV` | حالت اجرا | در محیط واقعی حتماً `production` بگذارید |

## حالت توسعه (بدون کلید)

اگر کلید کاوه‌نگار/Resend تنظیم نشده باشد و `NODE_ENV=production` **نباشد**، کد OTP به‌جای ارسال واقعی روی **خروجی همین کنسول سرور** چاپ می‌شود:

```
[otp] phone -> 09121111111 : (delivery via dev stdout)
```

این فقط برای تست محلی است؛ کد هرگز در پاسخ API یا مرورگر ظاهر نمی‌شود و در `NODE_ENV=production` بدون کلید، درخواست با خطای 503 «سرویس پیام‌رسانی هنوز تنظیم نشده است» رد می‌شود.

## API

| مسیر | توضیح |
|---|---|
| `GET /api/health` | سلام سرور |
| `GET /api/config` | وضعیت provider ها + پارامترهای OTP (برای تایمر UI) |
| `POST /api/auth/request` | `{channel:"phone"|"email", target}` → ارسال کد |
| `POST /api/auth/verify` | `{channel, target, code}` → توکن + کاربر (پیدا یا ساخت خودکار حساب) |
| `GET /api/me` | کاربر + پیشرفت/تنظیمات ذخیره‌شده |
| `PUT /api/me/progress` | ذخیره `{progress, settings, updatedAt}` |
| `POST /api/auth/logout` | ابطال سشن فعلی |
| `POST /api/auth/link/request` | درخواست OTP برای تماس دوم |
| `POST /api/auth/link/verify` | تأیید تماس دوم؛ اگر متعلق به حساب دیگری باشد → `contact_conflict` |
| `POST /api/auth/link/confirm` | انتقال امن تماس: علاوه بر کد تماس جدید، کد تازه‌ی تماس اصلیِ حساب فعلی هم لازم است — ادغام خودکار وجود ندارد |

همه‌ی مسیرهای `Authorization: Bearer <token>` را می‌پذیرند (به‌جز health/config و request/verify).

## امنیت

- کد OTP فقط به‌صورت هش ذخیره می‌شود؛ تک‌مصرف؛ ۱۸۰ ثانیه اعتبار؛ حداکثر ۵ تلاش.
- نرخ‌ها: ارسال مجدد هر ۶۰ ثانیه؛ هر شماره/ایمیل ۵ در ساعت؛ هر IP ۳۰ در ساعت (env قابل تغییر).
- توکن سشن ۳۲ بایتی تصادفی، فقط هش در DB، انقضای کشویی ۳۰ روزه.
- هیچ اطلاعاتی درباره‌ی ثبت‌بودن شماره/ایمیل قبل از وریفای افشا نمی‌شود.
- شماره فقط با قالب دقیق `09XXXXXXXXX` (ارقام فارسی/عربی خودکار نرمال می‌شوند)؛ کد کشور و شماره‌های خارجی رد می‌شوند.
- کدها در لاگ تولیدی نمی‌آیند (فقط stdout در dev).
